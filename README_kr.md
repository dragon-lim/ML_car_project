# 라인 트레이서 (Line Tracer) — 진행 상황

1학년 강의실 실내에 설치된 라인이 아니라, **야외에 테이프로 설치한 라인**을 따라가는 자율주행을 목표로 한 프로젝트입니다. 야외 환경이라 햇빛·그림자·반사 등 변수가 많아, 상대적으로 빛이 안정적인 **일몰 전후 약 2시간**만을 작업 시간으로 정해 촬영 및 주행 테스트를 진행했습니다.

## 📂 Data Collector – Autonomous Driving Dataset Tool

### 📌 개요
`datacollector/` 디렉토리는 **카메라 영상 + 차량 조향/모터 제어 정보**를 **동시에 수집하여 자율주행 학습용 데이터셋을 생성**하는 도구를 제공합니다.

- 자동차를 **키보드로 수동 조작**하면서
- 매 프레임마다 **이미지 + 조향각 + 모터 속도**가 저장됩니다.
- PyTorch/TensorFlow 학습에 바로 활용 가능한 형태의 데이터셋 생성이 목적입니다.

### 📁 디렉토리 구조

```
datacollector/
├─ camera/
│   ├─ __init__.py
│   ├─ camera_capture.py    # OpenCV 기반 영상 캡처 + 저장 모듈
│   └─ webcam_test.py       # 카메라 테스트 유틸
│
├─ hw_control/
│   ├─ __init__.py
│   ├─ drive.py             # 차량 주행 제어 (키보드 입력 처리 포함)
│   └─ input_utils.py       # Raw 키 입력 처리 모듈
│
├─ tools/                   # 데이터 정리·라벨 검증 도구 모음 (아래 "라벨 검증 도구" 참고)
├─ img-collector.py         # 🚗 + 📷 데이터 수집 통합 실행 스크립트
└─ readme.md
```

### ⚙️ 구성 요소 설명

**1. drive.py — 차량 주행 제어 모듈**
- Jetson Nano + L298N + MG996R 기반 제어 로직
- 기능
  - 전진/후진 제어
  - 조향(서보) 제어
  - 속도 조절
  - 역방향 입력 시 안전 정지
- 외부에 제공하는 주요 API
  - `run_drive_control(stop_flag)`
  - `get_current_state()` → `(servo_angle, motor_speed)` 반환

**2. camera_capture.py — 영상 캡처 모듈**
- OpenCV로 웹캠 프레임을 읽고 저장
- 기능
  - 일정 주기(`save_interval`)마다 이미지 저장
  - 라벨 자동 기록(CSV)
  - 파일명에 각도/속도 포함 → 학습 라벨링 자동화

**3. img-collector.py — 통합 실행 스크립트**
- 🚗 주행 스레드 + 📷 카메라 스레드를 동시에 실행
- 기능
  - stop_flag 공유로 깨끗한 종료
  - 주행 상태와 이미지가 시간적으로 동기화
- 실행 예시

```bash
sudo python3 img-collector.py
```

### 🔌 H/W Wiring Guide

**▶️ L298N DC Motor Wiring**

| Jetson Nano Pin (BOARD) | L298N Pin | 기능 |
|---|---|---|
| 33 | ENA / PWM | DC Motor 속도 제어 |
| 31 | IN1 | 방향 제어 1 |
| 29 | IN2 | 방향 제어 2 |
| GND | GND | 공통 접지 |

⚠️ **주의**
- Jetson의 5V와 L298N의 5V OUT을 **절대 연결하지 말 것** (전압 충돌 위험)
- DC 모터 전원은 외부 12V 또는 7.4V 배터리를 사용하길 권장

**▶️ MG996R Servo Wiring**

| 서보 배선 | 연결 위치 |
|---|---|
| 갈색 (GND) | Jetson GND |
| 빨강 (VCC) | Jetson 5V |
| 노랑 (PWM) | Jetson BOARD 핀 32 |

   │               • 키보드 입력 처리

## 라벨 검증 도구 (label_check_v3.py)

`datacollector/tools/label_check_v3.py`는 사진에 찍힌 실제 차선의 기울기를 계산해서, 파일에 저장된 라벨(조향각)과 방향이 맞는지 검증하는 도구입니다.

**동작 원리**
1. 초록·노랑 테이프를 HSV 색상 범위로 검출합니다.
2. 화면 위쪽과 아래쪽에서 검출된 픽셀의 평균 위치를 각각 구하고, 두 점을 이어 기울기(편차)를 계산합니다.
3. 계산한 방향(왼쪽/직진/오른쪽)이 라벨의 방향(30·60 / 90 / 120·150)과 다르면 MISMATCH로 표시합니다.
4. 같은 장면이 연속으로 여러 장 저장된 경우 하나의 사건(cluster)으로 묶어, 실제로 확인해야 할 건수를 줄입니다.
5. 화면에 초록과 노랑 테이프가 함께 잡히는 교차·합류 장면은 계산이 불안정해서 mixed_scene으로 분리하고, 신뢰도가 낮은 참고용으로 따로 관리합니다.

<img src="images/06_label_check_visualization.png" width="480">

*그림. 계산 원리 시각화. 빨간 점(위쪽 평균)과 파란 점(아래쪽 평균)을 이어 기울기를 구합니다. 이 사진은 라벨이 90(직진)이었지만 실제로는 좌회전 구간이었던 오류 사례입니다.*

**후속 처리**
- `filter_high_confidence.py`: 육안 확인에서 신뢰도가 높았던 조건(90인데 편차 ±30 이상 등)만 골라냅니다.
- `relabel_high_confidence.py`: 골라낸 사건의 프레임 파일명을 계산된 각도에 맞게 일괄 수정합니다. 실행 전 원본을 자동으로 백업합니다.

**결과**
- 육안으로 확인한 의심 사례 11건 중 10건이 실제 라벨 오류였고, 1건은 교차 장면에서 도구가 잘못 판단한 경우였습니다.
- 서로 다른 3개 촬영 배치에 적용한 결과, 단일 장면의 MISMATCH 사건이 550→115건, 443→90건, 673→99건으로 줄었습니다(약 80% 감소).

**한계**
교차·합류 장면에서는 도구가 부정확할 수 있어 자동 수정 대상에서 제외했습니다. 또한 검증과 재검증에 같은 도구를 사용했기 때문에, 감소율은 독립적인 정확도 지표가 아니라 도구 기준의 개선 정도로 봐야 합니다.

## 현재 상태

학습 파이프라인(데이터 수집 → 품질 필터링 → 라벨 검증·수정 → 학습 → TensorRT 변환 → 실주행 테스트)은 일련의 과정으로 구축 완료. 앞으로는 실주행 안정성 향상(차선 이탈 시 대응 개선, 클래스 불균형 추가 보정)을 중심으로 계속 작업할 예정.

## 향후 계획

현재는 조향각을 30/60/90/120/150도 중 하나로 고르는 **분류(classification)** 방식으로 학습하고 있는데, 이 경우 모델이 5단계 각도 중 하나를 딱 잘라 예측하다 보니 실주행에서 조향이 계단식으로 뚝뚝 끊기는 경향이 있었다. 앞으로는 **회귀(regression, 선형회귀)** 방식으로 학습 방법을 전환하여, 모델이 "87도", "112도"처럼 연속적인 각도 값을 직접 예측하도록 바꿀 계획이다. 이를 통해 조향 전환이 훨씬 자연스럽고 부드러운 주행을 구현하는 것이 목표다.
